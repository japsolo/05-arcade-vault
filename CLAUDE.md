This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Arcade Vault: an online platform to play games and compete for the highest score. The project follows Spec-Driven Development (`/spec` and `/spec-impl`), using the skills from `Klerith/fernando-skills` (`npx skills@latest add Klerith/fernando-skills`). SPEC 01 (`specs/01-mvp-pantallas-visuales.md`) implements the visual MVP: all five screens with mock data and no real games. `references/` holds the original prototype (React + Babel, ignored by ESLint); it is the visual source of truth.

## Architecture notes

- App Router only (`app/`); path alias `@/*` maps to the repo root.
- `next.config.ts` enables `cacheComponents`, `partialPrefetching` and `experimental.agentFeedback`. `cacheComponents` changes caching/dynamic-rendering semantics, so check the docs before using data fetching or dynamic APIs.
- Tailwind v4 is wired through a Turbopack rule (`@tailwindcss/turbopack` loader for `*.css`) rather than PostCSS. Theme tokens live in `app/globals.css` (`@theme inline`, light/dark via `prefers-color-scheme`).
- Routes: `/` (home/landing), `/biblioteca` (library), `/juegos/[id]` (detail), `/juegos/[id]/jugar` (simulated player), `/acceso` (auth), `/salon` (hall of fame), `/acerca-de` (about + contact form). UI is Spanish.
- The home (`app/page.tsx`) is a server component built from `components/home/*`; only `Reveal` (IntersectionObserver adds `.in` to `.reveal` sections) and `home-ctas.tsx` (session-dependent CTAs) are client components.
- The About page (`app/acerca-de/page.tsx`) is a server component that reuses `Reveal` from the home; its only client component is `components/about/contact-form.tsx`. The form posts to the Server Action `sendContact` (`app/acerca-de/actions.ts`) via `useActionState`, which sends one email to the team with the `resend` SDK. Validation, limits, the `ContactState` type and the escaped HTML/text email template live in `lib/contact.ts` (shared by client and server, no secrets). The form uses uncontrolled inputs: React 19 resets the form after each action, so on error the values come back in `state.values` as `defaultValue`. A hidden `website` field is a honeypot (filled → reports success without sending).
- Server-only env vars (in `.env`, git-ignored; keys listed in the committed `.env.template`): `RESEND_API_KEY` and `CONTACT_TO_EMAIL`. Mail is sent from `onboarding@resend.dev`, which Resend only delivers to the Resend account owner's address, so `CONTACT_TO_EMAIL` must be that address. Never expose them with `NEXT_PUBLIC_`; read them only inside the Server Action.
- Supabase connection (SPEC 04, `@supabase/ssr`): `lib/supabase/server.ts` (`await createClient()` over `cookies()`, for Server Components/Actions/Route Handlers; create one per request), `lib/supabase/client.ts` (`createClient()` for `"use client"` components) and `lib/supabase/proxy.ts` (`updateSession`, called from the root `proxy.ts` — Next 16's replacement for `middleware.ts` — to refresh the session cookie; its `matcher` skips static assets and images). Never import `server.ts` or `proxy.ts` from client components. The project has no tables, migrations or generated types yet, and nothing uses the clients; auth and data come in later specs. Env vars `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (`sb_publishable_…`, public by design; data security will come from RLS). Never add a secret/`service_role` key. `scripts/supabase-check.mjs` (`npm run supabase:check`) verifies them.
- Mock data lives in `lib/games.ts`, `lib/scores.ts` (deterministic `seededScores`) and `lib/home.ts` (home copy, activity, top players, FAQ). Components are in `components/`; styles reuse the classes in `app/globals.css` rather than Tailwind utilities.
- Session is simulated: `lib/session.ts` + the `useSession` hook (`lib/use-session.ts`) read `localStorage` (`av_user`, `av_scores`) through `useSyncExternalStore`. There is no context provider: each component must call the hook itself so it hydrates with the server snapshot (`null`) even inside `Suspense` (a context made `Nav` hydrate with the user and mismatch). Don't use `useEffect` + `setState` for this (the `react-hooks/set-state-in-effect` lint rule rejects it).
- Pages that read `params` do it inside `<Suspense>` (see `app/juegos/[id]/page.tsx`) to keep the App Shell shared; `Nav` is also wrapped in `Suspense` because `usePathname` can suspend with `cacheComponents`.
- `app/layout.tsx` types its props with the global `LayoutProps<"/">` helper (generated route types), not a hand-written props type.
